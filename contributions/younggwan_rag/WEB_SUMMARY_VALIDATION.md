## 변경 결과

문서 한 개 선택 → 선택 적용 → 예상 호출 수 확인 → API 설정 적용 → **전체 요약 생성** 흐름을 추가했습니다.

조회에는 생성 API 호출이 없습니다. Phase 5 저장 결과가 없는 새 문서에도 같은 경로를 사용합니다.

생성은 별도 작업 스레드에서 수행하되 SQLite 연결은 그 스레드에서 새로 열고 닫습니다.
질문·상태 조회용 서버를 장시간 생성 호출로 막지 않으며, 진행 중 선택 변경과 추가 생성
요청을 제한합니다. C/D의 저장 벡터는 검증하지만 요약을 위해 질문 임베딩을 호출하지 않습니다.

기존 요약 복구 클라이언트의 `_response_payload`가 공통 클라이언트의 새 키워드 인수를
받지 못하던 오류도 수정했습니다. 응답 처리 옵션을 전달하며 프롬프트·출처 검사 기준은 유지합니다.

## 저장과 복구

- 문서·모델·원문·인덱스에 연결된 고정 실행 ID와 기존 source-unit cache를 사용합니다.
- API 호출 직전 예약을 저장하고, 완료 배치는 다시 호출하지 않습니다.
- 실패·중단 배치를 버튼 반복 클릭으로 유료 재시도하지 않습니다. `web_job.json`과
  `journal.json`에서 오류·미처리 상태를 먼저 확인해야 합니다.
- 요약 호출 한도는 질문 세션 한도와 별도이며 문서·모델별로 누적됩니다. 기본 30회·600,000바이트입니다.
- 입력 응답 수신율·청크 검사 완료율과 요약 의미 정확도는 구분합니다. 사람 검토를 자동 통과시키지 않습니다.
